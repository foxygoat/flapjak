## LDAP Independence Day

flapjak now uses its own ldap server library! This swaps one
higher-level dependency (jimlambrt/gldap) with a lower-level dependency
(go-asn1-ber/asn1-ber). There is also a dependency on go-ldap/ldap/v3
for the tests. These were already indirect dependencies.

Abandon operations are handled now and do not return an error back to
the client. nslcd seems to issue abandons so was logging errors when
these failed.

The internal database now keeps the types of the attributes (string,
number or bool). This fixes the wire formatting of booleans which should
have been upper case but were previously lower case as generated by
strconv.FormatBool. It also tightens the acceptable attribute values
requiring all the values of an attribute be the same type. An existing
database with mixed type multi-value attributes will now fail to load.

Filters support ranking (<=, >=) now that values can properly be ranked.
Substring filters are implemented too, as is approximate match, which is
currently handled as an exact match.

Connections now have a lifetime. An idle connection is closed after five
minutes and a single response write is given thirty seconds, neither of
which gldap had. Clients that hold a connection open between lookups,
which nslcd does by default, will reconnect where they previously did
not.

The server is stricter about the protocol. A control marked critical
that the server does not recognise is refused with
unavailableCriticalExtension rather than ignored, and a search that sets
a size or time limit now has it enforced.

StartTLS and Who Am I are answered as extended operations, and SIGINT or
SIGTERM shuts the server down gracefully: connections stop taking new
requests and in-flight searches are given a few seconds to finish.

The root DSE now reports its objectClass. Its attributes were built with
a key that did not match how attributes are looked up, so the entry
appeared to have no objectClass and a search for one did not return it.
